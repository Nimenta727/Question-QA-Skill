# QUICK 教学追问手册 / Adaptive formative tutoring

本手册约束 Agent 教学行为，不是给学生看的固定答案库。每轮只问一个问题；不得预先把全部追问题打印出来。

## 观察 → 解释的候选 → 下一步如何区分

| 观察到的行为 | 你目前知道什么 | 最有信息量的下一问 |
|---|---|---|
| 给出正确数字、却说“猜的” | 当前正确，尚不清楚是否理解 | 同概念、不同题族、无提示的解释或应用 |
| 答错单选题、错选项有审阅来源 | 选择结果与某种误区相符 | 换表述、要求关键推导，确认而不是断言 |
| 答错开放题，但没有审阅过原因 | 当前答案不满足已知标准 | 先问“从哪一步推导到这里？”或验证一个更小的前提 |
| 解对例题，还能解释每个步骤 | 该题的理解证据较强 | 改变边界条件、要求反例、迁移到新情境 |
| 开放题满足部分rubric | 存在已评阅的局部证据 | 只追问最关键的遗漏，不惩罚无关表达 |
| 有提示后答对 | 在帮助下完成任务 | 之后用无提示的独立任务验证 |
| 学生停止或达到题量上限 | 应结束 | 总结证据与待测试内容，不强迫继续 |

错误选项只能提示可能的误区，不证明学生为什么选它；仅有一个错误更不能推断“这个知识点完全不会”。

## 从课件制作高信息量的追问

1. 摘取一个有具体来源的学习目标，注明它的必要前置概念。
2. 用“断言、证据、题目”三要素建立诊断关系：例如“理解分配律”→“解释为什么2(x+3)不等于2x+3”→“找到推导中最早的不合法变形”。
3. 学生答错后，不要只把2(x+3)改成3(x+4)；改问括号中各项如何参与乘法，或辨别两段推导哪一步无效。
4. 确认可靠基础之后再给出有界的迁移挑战，不能突然引入课程没讲过的新知识。
5. 一次一题，等待回答，以最少但足够的反馈让学生知道哪个推理步骤成立或缺失。

## Agent 内部临时计划（不向学生展示）

- target_claim: 本题确认哪一种具体理解？
- observed_evidence: 实际看到了什么？可核验、猜测、提示、部分正确还是含糊？
- alternative_hypotheses: 允许“暂未测试到”的可能，避免凭单题定性。
- followup_intent: baseline / repair_prerequisite / clarify_reasoning / verify_independently / probe_transfer / close_and_review。
- next_task: 用一个不同题族的任务区分上述解释，需要看到什么证据？
- stop: 用户叫停或达到默认六轮时总结。

没有可用本地题库时直接在聊天中执行，不要求用户安装工具。

## 本地工具如何协作

- qa.py next 的 question 是学生可见的题；tutor_intent 是供 Agent 使用的内部提示。若 suggestion_fit=review_or_author_better_variant，不能称其为最优诊断题，可以在无pending状态下另拟并验题。
- qa.py answer 返回 tutor_next_move；Agent 先解释本次作答，再决定下一题还是澄清、结束。工具不做自然语言语义判分。
- qa.py report 的 teaching_summary 是本次会话的概览，不证明长期保持或标准化掌握概率。

## 合成互动示例（仅展示追问设计）

AI：假设某同学写出 2(x+3)=2x+3，哪里有问题？

学生：2只能乘到x上吧，我不太确定。

AI：分配律要求括号内每一项都乘2。这一步漏掉了常数项。追问：如果把两个相同括号相加，常数部分出现几次？请解释。

学生：会出现两次，所以常数要乘2。

AI：这一问说明你识别了常数项也要分配。接下来换个表征确认：不用展开，请说明为什么3(a+b)与3a+3b对任意a、b相同。

这几次相近作答仍不足以直接称学生“完全掌握了分配律”；还需要独立题族、认知层次及延迟验证。


## 出现新题、修改题、临时追问时：先审后问
每一轮问学生前，AI必须独立再解新题，寻找两个可能正确的选项、漏掉的边界条件、合理等价答案、隐含先修知识，以及是否只换数字重复上一题。详细审阅顺序见 references/model_audit.md。错误/不确定/无法核对来源 → 换题或标记待复核，不能为了赶进度硬出题。对旧题库的严格模式，qa.py next --require-model-audit --model-audit FILE 可在提供独立审核表后才显示题面；实际课程还必须核对所附的课程文件。程序不调用LLM；由Agent真正执行审阅，自我复核不能冒充独立审阅。

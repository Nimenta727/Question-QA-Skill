# 2026-11-21 — 双智能体交替命题和严格审核引擎

## 本次改动
- 新增 scripts/dual_agent.py，构建**实际可调用模型**的受控轮替流程：作者独立生成新题 → 审阅模型只看到学生题面先盲解 → 同一审阅模型得到标准答案后反向批判 → 已存在的 model_audit.verify 对题库SHA、课程SHA、答案一致性、九维报告与风险逐项阻断 → 失败则带明确问题反馈给作者重写。
- 真正运行时分别通过固定HTTPS OpenAI Responses API发起无会话状态的作者模型、审阅模型调用；模型由用户显式指定。无API key时失败，不伪造模型完成审稿，文档不把两次调用称为独立实名审阅。
- 每轮有固定上限(1–3)，每轮最多3次模型API调用；输出目录必须不存在，文件O_EXCL+POSIX 0600、目录0700，保留每次草稿、盲审证据、逐题审核包、结构校验结果及简洁轮次历史。
- 盲审输入通过允许字段白名单过滤，**绝不发送命题者标准答案、解析、别名或rubric**；审阅第二阶段必须保留与盲审第一阶段完全相同的独立答案和独立推理，防止看到标准答案后悄悄改写证据。
- 任何缺失、拒绝、错答案、课程来源不可核验、审核角色绑定错误、盲审风险未解决或轮数耗尽都不能输出approved-bank；不存在“模型调用失败仍判过”的逃逸通道。
- 真实课程来源必须显式指定--allow-remote-source才能发送至模型服务，默认不上传。真实学生隐私信息不应作为源文件提交。API key仅从环境变量读取，响应不存到服务端对话状态(store=false)。
- 这些机制只能证明软件流程与记录一致，不代表模型真的准确审题或两模型在组织层面真正独立，更不替代有资质教师审核。

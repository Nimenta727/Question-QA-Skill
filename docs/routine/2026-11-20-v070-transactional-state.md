# 2026-11-20 — v0.7 多进程学习状态锁与原子备份恢复 / Concurrent local transactions

## 本次改动
- 新增 scripts/state_store.py，使用 Linux/macOS fcntl.flock 和 Windows msvcrt.locking 的**系统原生排他文件锁**，由主CLI将整个读-改-写会话封装成锁事务，防止两个并发进程互相覆盖pending或历史。
- 锁文件 .lock 永久存在但锁资源由系统在进程退出时释放，不会出现“进程崩溃后必须删除僵尸锁文件”的问题；超时明确报忙碌。仅保证本地文件系统，不宣称跨NFS/云同步分布式锁。
- 每次提交前校验旧学习状态，原子写入 .bak（上一次有效已提交状态），然后用同目录临时文件、fsync和os.replace原子提交新JSON。绝不把原文件里的异常JSON覆盖到好的备份。
- 新增 state-check：仅输出当前/备份是否完整、回答计数与哈希；state-recover --confirm：需明确用户操作才从上次有效备份原子恢复，恢复可能丢失最近一次操作，保留原备份。
- 状态默认无原始学生回答，但是仍视为隐私资料；.bak 和 .lock 必须排除Git追踪、按操作系统权限保护。不进行云上传。

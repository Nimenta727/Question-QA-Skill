# Question-QA-Skill v0.9.0 — Authenticated Appeals & Tamper-Evident Review

- Introduced a standard-library-only, offline **local reviewer capability registry**. Administrators provision 32-byte random tokens; the registry stores salted PBKDF2-HMAC verifiers and permits role checks and revocation, with credentials read from protected local files rather than CLI arguments. Identity is credential possession, not verified actual human identity.
- Added an HMAC-SHA256 **linked correction audit ledger**: sequence numbers, prior-record MACs, captured appeal snapshots and effective grade validation. A separate HMAC-signed .audit-policy prevents simple removal of the audit field to silently downgrade protected grading, while an independently retained checkpoint receipt helps detect rollback to an older valid signed state. These controls are conditional on key and file custody and do not make local data unalterable.
- Secured appeal correction now requires an enrolled active reviewer credential **plus** the audit key; v0.8 unprotected grading remains backward-compatible but explicitly marked as not authenticated. Protected rollback and local deletion require additional explicit acknowledgments. No raw student responses or plaintext secrets are persisted by the new audit modules.
- Extended the pseudonymous independent reviewer trial helper with **post-freeze third-party adjudication**: untouched A/B first-round score hashes must match the frozen record; only disputed rubric criteria can be decided by C. A separately authored synthetic expert-reference comparison tool is included where present; its output and checks do not establish true expert correctness or real participation.
- Maintained the previously evaluated v0.2 diagnostic scoring and existing negative/inconclusive external dataset findings. No BKT/IRT refitting on exposed held-out data, no unverifiable claims of actual study participation, and no raw learner datasets bundled.
- Versioned release uses six Linux/Windows/macOS × Python 3.9/3.12 test combinations and full fresh-extraction/SHA256 checks. Every repository modification has a dated record in docs/routine.

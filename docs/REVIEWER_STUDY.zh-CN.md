# v0.7.0 双审阅者一致性研究协议（工具已做，真实实验未开展）

**当前状态：仅完成研究工具及合成数据验收，尚未招募或让真实教师、学生参与实验。** 两人评分一致不代表给对分数；还必须有外部专家标注标准答案/评分依据并检查题目公平性。

## 推荐的真实研究步骤
1. 与负责教师/教育机构明确批准流程，使用合适的知情同意、最小化个人数据、匿名代号和必要的家长/监护人同意；不采集未授权学生答卷。
2. 预先固定题库、评分rubric、知识点、样本范围、纳排条件和主要分析终点，先做独立命题审核；不要看结果以后改阈值。
3. 每个答案采用随机分配的**两名真实且独立的审阅者**；同题、同rubric，但审阅者在提交首轮评分前不能看到彼此答案。记录每条标准0、0.5或1分。对模糊、涉及抄袭或不适用条目作明确复核流程。
4. 先冻结首轮两个评分包，再对分歧条目分配第三位独立仲裁者。仲裁记录可以是隐私保护的加密离线工作流，不必传入本仓库。
5. 只用脱敏、按案例ID合并的分数表计算一致率、按答卷案例聚类的95% bootstrap区间、二次加权 Cohen Kappa、争议比例与仲裁完成率；另由专家独立审查错误判分情况，避免“大家一起错”的假一致。
6. 公开报告只使用汇总值；数据量不足、特殊题型、审阅者不同背景及不同课程都要报告不确定性与外推限制。没有真实验证的结果不可声明模型已公平或正确。

## 本地聚合分析
私有JSON示例（合成）位于 examples/sample_reviewer_study.json：

    {
      "study_type":"synthetic",
      "cases":[
        {"case_id":"anon-001","scores_a":[1,0.5,0],
         "scores_b":[1,1,0],"final":[1,0.5,0]}
      ]
    }

final是可选的仲裁后得分，若存在则长度与rubric一致，并且**不能修改双方已经一致的标准**。无final且有争议会计入unresolved_cases。真实数据的study_type可写real_private_self_declared，但仅是用户自己声明；工具不会验证真人参与。

    python scripts/reviewer_study.py --input examples/sample_reviewer_study.json --bootstraps 200 --output reviewer-study-aggregate.json

输出只含计数、逐条一致率、整题一致率、加权Kappa、平均分数差、争议数量、可信区间等汇总值；case_id和原始答案不会输出。全同类得分的Kappa可能无法定义，届时是null，不能伪装成1。此工具不含真实身份认证或自动语义判分。
